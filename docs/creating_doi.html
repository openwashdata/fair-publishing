5  Creating a release and a DOI

A Digital Object Identifier (DOI) makes the dataset citable. It points at a fixed version of the data in an archive that outlives the repository. Zenodo assigns one for every release of a GitHub repository it watches. This chapter writes the citation files, checks that the package is ready, creates the release and brings the DOI back into the package.

5.1 Write the citation files

update_citation()

The call writes three files from DESCRIPTION. CITATION.cff is what GitHub reads for its “Cite this repository” button. inst/CITATION is what citation("yourpackagename") prints in R. .zenodo.json is what Zenodo reads when it archives a release. From that file Zenodo takes the resource type (Dataset), the openwashdata community, the creators with their ORCID iDs, the license and the keywords, so that the record needs no edits by hand. When DESCRIPTION names a source article in X-schema.org-isBasedOn, the citation files cite it next to the data package.

Commit the three files and push. Zenodo reads .zenodo.json from the release, so it has to be in the repository before the release is created.

5.2 Check that the package is ready

check_publication_readiness()

The function reads the package and reports, item by item, what is in place and what is missing. It covers the metadata, the dictionary, the documentation, the citation files and the check workflow, and for every gap it names the step that closes it. It writes nothing, so run it as often as you like, and go back to the chapter it points to until no item fails. Before the first release, the DOI is the one expected gap.

5.3 Connect the repository to Zenodo

Log in to Zenodo with your GitHub account. Open the menu next to your email address in the top right corner, choose “GitHub”, find your repository in the list and flip its switch to “ON”. From now on Zenodo archives every release of the repository. Each release gets its own version DOI, and the record carries one concept DOI that always resolves to the latest version.

5.4 Create the release

Set Version in DESCRIPTION to the version you release, for example 1.0.0 for the first publication. Run update_citation() once more, so that the citation files carry the version, and devtools::build_readme(), so that the README names it. Commit and push.

On GitHub, open the repository, click “Releases” and “Draft a new release”. Create a tag with the version and a v in front, such as v1.0.0, give the release the same name and a short description, and publish it. Zenodo picks the release up and creates the archive. This can take up to an hour. The DOIs then appear on the record and on your Zenodo GitHub page.

Open the record on Zenodo and check it. The resource type is Dataset, the community is openwashdata, the creators and the license are right. All of this came from .zenodo.json. If something is wrong, fix it in DESCRIPTION, run update_citation() again for the next release, and correct the record once in the Zenodo editor.

5.5 Bring the DOI into the package

Use the concept DOI, the one Zenodo shows under “Cite all versions”. It stays the same across releases, so a citation always resolves to the latest version, while the version in the citation file says which one was used. Back in RStudio, write it into the citation files, the README and the metadata with two calls:

update_citation(doi = "10.5281/zenodo.11185699")
update_metadata()

update_citation() regenerates the citation files with the DOI, adds the DOI badge to README.Rmd and rebuilds README.md. update_metadata() carries the DOI into the JSON-LD of the site. Run check_publication_readiness() once more, then commit the changed files and push. The pkgdown workflow rebuilds the site, and the citation in the README and on the website now shows how to cite the dataset.

A package with a Zenodo DOI appears in the openwashdata data catalogue within a week.

5.6 Later versions

When the data or the documentation changes after publication, raise the version in DESCRIPTION, run the steps of this chapter again and create a new release. Zenodo archives the new version under a new version DOI, and the concept DOI keeps resolving to the latest one. The download links in the README point at the release tag of the version in DESCRIPTION, so that a citation of a version leads to the same files later.

5.7 ETH Research Collection submission

Note

This section applies only to researchers at Global Health Engineering, ETH Zurich.

For a submission to the ETH Research Collection, go to the research data section and choose “dataset” as the submission type. Under organisational unit, select “tilley”, and set the license to “Creative Commons Attribution 4.0 International”. These settings match the data package and keep the data open while protecting your rights as the creator.
